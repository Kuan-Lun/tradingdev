TradingDev 的產品介面以標準 MCP 為主，後端不綁定特定 LLM 供應商。產品範圍不包含真實下單。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md

Application services 負責跨領域流程；MCP、CLI 與 Dashboard 以不同方式使用這些能力。SQLite 保存索引和摘要，檔案系統保存 revision、快取與完整產物。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md

準備工作會追問缺少的研究輸入；準備本身不執行正式回測。只有後續明確同意才會提交計畫。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/execution_plans.md

這是目前主線的概念流程。正式名稱可在 src/tradingdev/app、mcp/tools、mcp/workers 與 adapters 中查閱。準備與執行是不同階段；preflight 不下載正式歷史行情，也不產生績效結果。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/src/tradingdev/mcp/server.py

MCP server 在建立服務時註冊 strategy、data、execution、jobs、runs、history、artifacts、research notes、feature requests 與 ML 等工具。這是按責任分組的簡報版，而非完整工具目錄。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/src/tradingdev/mcp/server.py 來源：https://github.com/Kuan-Lun/tradingdev/tree/9e502ce/src/tradingdev/mcp/tools

MCP tools 主要負責協定與資料轉換；工作流程及狀態轉移由 application 層服務協調。部分流程仍由 worker 負責協調，例如最佳化搜尋與樣本外測試。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md

策略版本、執行 manifest、計畫、工作、run 與 artifact 各自有身分和責任，不能把它們當成同一筆資料。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md

模型須取得策略構想、標的、期間與 K 棒頻率；缺項要追問。有效的本金、成本及年化假設由共用政策處理，不能從範例或其他市場暗中猜值。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/AGENTS.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/strategy_contract.md

建立與修訂分開處理。revision 保存固定程式及基礎設定；修改版本不會沿用舊版執行資格，已保存的執行結果不會因後續策略變更而重新解讀。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/strategy_contract.md

generated strategy 的合成資料檢查涵蓋固定 fixture 和訊號契約；它不代表真實行情可用、策略暖機充分或交易語意正確。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/strategy_contract.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/execution_plans.md

Preflight 是離線準備：不下載正式行情、不執行回測或訓練、不產生績效。修改要求需要重新準備與檢查，最初請求或沉默不代表同意。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/execution_plans.md

行情報告會保留資料身分與檢查結果。缺值不會被當成零回報，特徵不會用未來觀測回填過去資料；快取發布採不可變版本與原子更新。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/run_artifacts.md

CLI 同步回測與 MCP 背景 job 的入口不同，但都使用共用的策略資格、manifest 與績效模型。Job 與 Run 分開描述：一個是執行流程，一個是保存結果。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/src/tradingdev/app/job_service.py

Signal 與 volume 模式採不同的引擎和指標基礎。volume mode 無初始本金報酬基準，應以金額 PnL 及回撤解讀，不把缺失報酬當作零。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/src/tradingdev/domain/backtest/engines.py 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/performance_artifacts.md

最佳化使用自己的日期切分，不同時套用 walk-forward。固定比較由父工作保存候選帳本，失敗或未執行的候選不會被默默省略。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/run_artifacts.md

ML 研究是同步的獨立介面，不會自動建立一般 backtest run，也尚未接入回測 Dashboard 或 CLI。簡化持有期統計不等同包含完整交易成本的交易回測。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/ml_research.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/src/tradingdev/mcp/tools/ml.py

保存的 performance artifacts 是計算結果的快照；歷史查詢不會用今日的 metric catalog 重新計算舊 run。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/performance_artifacts.md

一次 revision 可執行多次；每次執行都有自己的 manifest 與結果。ML dataset、model 和 ML leaderboard 有獨立身分，不可當成一般 run ID。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/run_artifacts.md

主線以 QuantStats 計算新 run 的報酬／風險統計，保留 VectorBT 的 closed-trade 統計。年化、daily drawdown 與日／月 PnL 需要每日或更細的宣告頻率；歷史指標會保留原始定義與 provider。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/performance_artifacts.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/src/tradingdev/domain/performance/catalog.py

RankingService 依 metric 前綴分派 run 與 signal 候選，兩者共用排序規則但使用不同資料模型。MCP leaderboard 工具已接上 RankingService；compare_runs 由 RunService 提供。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/src/tradingdev/app/ranking_service.py 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/src/tradingdev/app/run_service.py

CLI 的直接回測是同步入口，不使用 MCP 計畫確認或背景 supervisor。Dashboard 讀取已保存的 PipelineResult；回測報告透過 ReportService 組裝。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/ARCHITECTURE.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/README.md

來源與設定會隨成果保存，避免只留下聊天結論。研究筆記與報告是獨立產物，不會覆寫已保存的 run 或 ML leaderboard 歷史內容。 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/src/tradingdev/app/research_note_service.py 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/run_artifacts.md 來源：https://github.com/Kuan-Lun/tradingdev/blob/9e502ce/docs/reports.md
